# CareTaiwan 專案願景

日期：2026-07-01

CareTaiwan 是外籍家庭看護與家屬之間的照護協作工具。

這句話要寫死。後續加功能時，先問它是不是仍然服務這個定位。如果答案是否定的，就不要把功能塞進來。

## 這個專案不是什麼

CareTaiwan 不是：

- EMR。
- HIS。
- 醫療系統。
- 醫療器材。
- 看護管理系統。
- 長照 ERP。
- 排班系統。
- 薪資或扣款系統。
- 醫院掛號或醫療院所串接平台。
- AI 醫療建議或醫療分流工具。

這些領域各自有法規、專業責任、維運標準與導入流程。未來可以串接，但不能把 CareTaiwan 自己改成那些系統。

## 這個專案要做什麼

CareTaiwan 要做的是：

- 讓外籍家庭看護用很低的成本記錄照護日常。
- 讓看護能主動決定哪些紀錄要分享給家屬。
- 讓家屬透過 LINE 快速理解照護狀態。
- 讓照護交接、回診提醒、請假通知與家屬溝通有基本依據。
- 在隱私、資安與法律責任可以說清楚的前提下，逐步補上企業維運能力。

## 永遠優先順序

所有 issue、PR、產品提案與 AI 產出的程式碼，都要照這個順序檢查：

1. 看護使用成本最低。
2. 家屬快速理解。
3. 隱私優先。
4. 可離線或弱網路下可用。
5. 法規遵循與資料責任清楚。
6. 不提供醫療判斷。

如果兩個需求衝突，前面的原則優先。例外要寫進 [DECISIONS.md](./DECISIONS.md)，不能只留在聊天紀錄裡。

## 產品邊界

- 可以做日程提醒，但不能判斷醫療急迫性。
- 可以做照護紀錄，但不能取代醫療病歷。
- 可以做家屬通知，但不能把看護變成被監控對象。
- 可以做請假紀錄，但不能替雇主判斷勞資爭議。
- 可以補資安與合規流程，但不能宣稱已有未取得的認證。

## 成功標準

短期成功不是功能很多，而是：

- 新維護者看得懂專案要守的邊界。
- Contributor 知道怎麼提 issue 與 PR。
- 使用者知道這不是醫療判斷工具。
- 企業導入者看得出部署、資料保護與事件處理方向。
- AI 代理改程式時不會順手跨過醫療、個資或架構邊界。
