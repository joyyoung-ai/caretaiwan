# CareTaiwan 分支接手說明

日期：2026-06-30

這個 repository 是從原 CareTaiwan 開源專案延伸出來的維護分支，目前由中揚資訊股份有限公司接手。

## 接手聲明

CareTaiwan 原本是另一位作者在 GitHub 上開源的專案。從 README 可以看出，這是一個作者用業餘時間做出來的作品，曾經跑在 `caretaiwan.app`。後來服務下線，原因也很直接：長期營運、法規合規和使用者支援，已經超過一個人能穩定負擔的範圍。

中揚資訊股份有限公司接手的是這份開源程式碼後續的維護與功能整理。原作者的脈絡要留下來，原服務也不應被說成還在由原作者營運。之後改文件或改程式，都要保留作者原本寫下的研究背景和產品邊界。

## 原作者的專案精神

原作者在 README 裡寫得很清楚。這個專案一開始在意的是外籍家庭看護在台灣工作的現實，而不是功能堆疊。

看護可能只能在很短的空檔拿起手機，工作又長期疲勞，所以紀錄流程必須快，畫面也不能讓人想太久。資料先留在看護能掌握的地方；要分享給家屬，也應該是看護明確按下去的動作。家屬端接 LINE，則是因為台灣家庭本來就用 LINE 溝通，不是為了炫技。

原作者也刻意避開了幾件事：不做追蹤器，不把使用者資料當成產品燃料，不在沒有專業責任歸屬的情況下提供醫療建議。這些限制後續維護時要一直放在桌上。

所以新增功能時，不只問「做不做得到」。也要問：這對看護真的有用嗎？資料權利有沒有被拿走？法規和醫療責任有人扛嗎？

## 原作者遇到的困難

原作者停止維護，不代表專案沒有價值。比較像是，他很早就看到了後面真正花力氣的地方。

- 持續安全性修補與依賴更新。
- 個資法 / PDPA 合規與資料處理責任。
- 使用者支援、事件處理與營運監控。
- 服務上線後的 24/7 可用性與故障處理。
- 第三方服務與資料處理者管理，例如 Supabase、Vercel、LINE。
- 醫療內容的法律責任，尤其是非醫療背景作者透過 AI 工具發布醫療建議時可能造成的風險。
- 直接接觸外籍看護做訪談與研究的困難，因為其工作環境存在雇主權力、手機使用限制與發聲風險。
- 從朋友測試走向公開服務時，需要更正式的滲透測試、法律文件、資料處理協議與維運流程。

這些問題不能只放在 README 裡當背景故事。中揚資訊接手後，要把它們變成實際的工程、法務和營運待辦。

## 中揚資訊股份有限公司的維護原則

後續維護先照這幾條走：

- 保留原作者署名、授權資訊、研究脈絡與停止維護原因。
- 明確區分原作者已停止的線上服務與本分支的後續維護。
- 先補齊維護基礎：環境範例、部署文件、測試、資料庫 migration、營運 runbook。
- 優先修補會影響隱私、安全、部署可用性與法律定位的問題。
- 對外公開服務前，重新審查隱私權政策、服務條款、資料保留、刪除權、第三方處理者與事件應變流程。
- 不加入未經專業審查與責任歸屬確認的醫療建議、診斷、分流或治療內容。
- 若功能涉及醫療、照護決策或高風險個資，先建立清楚的產品責任與審核流程，再進入實作。

## 文件維護規則

- README 要說清楚：這是中揚資訊接手維護的分支，但原作者的敘事仍然保留。
- `../engineering/BUGFIX_PLAN.md` 不只列 bug，也要把原作者遇到的困難轉成維護風險。
- `AGENTS.md` 要提醒代理與維護者：不要抹掉原作者署名，也不要隨手把產品推進醫療建議範圍。
- 之後的 release note 要分清楚原專案既有行為、分支新增內容，以及實際營運方的部署設定。
